# Documentation Positioning Hypothesis Tree

## Objective

Help a first-time developer understand Fettle's differentiated value, install
the complete Python toolkit, and reach a trustworthy first result without
overstating supported surfaces.

## H1: Evidence-Led Product Story (Selected)

Hypothesis: leading with the agentic change loop, fail-closed evidence, and
delegation-safe policy will explain Fettle more clearly than a command inventory
because these capabilities form one differentiated trust boundary.

Falsification: a reader still cannot answer what Fettle does, why it differs
from lint/CI, what one install includes, or which external runtimes remain.

Evidence: the CLI, adversarial tests, artifact contracts, host capability matrix,
and distribution tests independently support these claims.

## H2: Exhaustive Feature Catalog (Rejected)

Hypothesis: putting every command above the fold will demonstrate breadth.

Falsification: the primary user journey becomes harder to find and planned,
advisory, and enforced capabilities become easy to conflate.

## H3: Universal Autonomous-Agent Claim (Rejected)

Hypothesis: describing Fettle as supporting every agent and language will improve
appeal.

Falsification: host and language surfaces have different verification levels,
making the claim inaccurate and weakening trust.

## Constraints

- Product claims must remain executable or traceable to code and tests.
- Missing tools and evidence remain visible; documentation cannot imply otherwise.
- The default package includes Python dependencies, not Git, browser binaries,
  agent CLIs, services, or non-Python toolchains.
- Historical release and research records retain their original context.
