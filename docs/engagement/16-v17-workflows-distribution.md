# 16 — v1.7.0 WP-18: Cross-environment workflow distribution

Status: implemented (this doc is the design record; written before code per
owner directive that XL work packages ship behind their own design doc).
Parent plan: [15-v161-audit-remediation.md](15-v161-audit-remediation.md) WP-18 (D3).

## Problem

The 17 guided workflows in `commands/` are Claude Code plugin commands
(`/fettle:quality` …). Owner directive D3: every capability must work in all
supported environments — VS Code, Codex CLI, Gemini CLI, OpenCode — and for
PyPI installs, not just the clone-into-plugins path. WP-17 made the command
content host-agnostic (plain `fettle <sub>` / `python3 -m fettle.<mod>`
invocations); this WP distributes it.

## Host format survey (verified against official docs, 2026-08-03)

| Host | Location | Format | Args | Invocation |
|---|---|---|---|---|
| Claude Code | plugin `commands/` (already works); standalone: `.claude/commands/fettle/` or `~/.claude/commands/fettle/` | md + YAML frontmatter (`description`, `argument-hint`, `allowed-tools`) | `$ARGUMENTS` | `/fettle:<name>` |
| VS Code | `.github/prompts/*.prompt.md` (workspace); user scope lives in profile storage (no stable path) | md + YAML frontmatter (`description`, `name`, `argument-hint`, `agent`, `tools`) | text after `/name` appended to prompt | `/fettle-<name>` |
| Codex CLI | `~/.codex/prompts/*.md` — top-level only, user scope only | md + YAML frontmatter (`description`, `argument-hint`) | `$ARGUMENTS`, `$1..$9` | `/prompts:fettle-<name>` |
| Gemini CLI | `~/.gemini/commands/fettle/<name>.toml` or `<repo>/.gemini/commands/fettle/<name>.toml` | TOML: `description`, `prompt` | `{{args}}` | `/fettle:<name>` |
| OpenCode | `~/.config/opencode/commands/` or `<repo>/.opencode/commands/` | md + YAML frontmatter (`description`, `agent`, `model`) | `$ARGUMENTS`, `$1..$9` | `/fettle-<name>` |

Findings that shaped the design:

- **Codex custom prompts are deprecated** (docs point to skills) but still
  functional. We ship the renderer anyway — it is ~15 lines — and note the
  deprecation in the step detail so users aren't surprised when Codex removes
  it. Skills migration is future work, out of scope here.
- Codex scans only **top-level** files in `~/.codex/prompts/` → flat
  `fettle-<name>.md` naming, no namespace dir.
- Gemini has no markdown command format — TOML with a `prompt` string; the
  stdlib cannot write TOML, so we emit it with a small escaper (multi-line
  `"""` strings; escape `\` and `"""`). `$ARGUMENTS` → `{{args}}`.
- VS Code has no argument placeholder; user text after the slash command is
  appended to the prompt. The rendered body keeps `$ARGUMENTS` and gains a
  preamble line defining it ("text the user typed after the command").
  Claude `allowed-tools` names don't map to VS Code tool names — `tools`
  frontmatter is omitted so the agent's defaults apply.

## Design

### Canonical source and bundling

`commands/*.md` stays the single source of truth (Claude plugin format).
setup.py's `_BuildPyWithRules` grows a third copy: `commands/*.md` →
`fettle/_commands/` (exactly the `rules/`→`_rules/` and
`templates/`→`_templates/` pattern). `_resources.py` gains `commands_dir()`
with the same resolution order: `CLAUDE_PLUGIN_ROOT` override → clone
`commands/` → wheel `fettle/_commands/`.

### fettle/workflows.py

- `parse_command(path) -> Workflow` — minimal stdlib frontmatter parser
  (simple `key: value` scalars; PyYAML must NOT become a runtime dep —
  pyproject `dependencies = []` is a hard constraint, see WP-11). Fields:
  `name`, `description`, `argument_hint`, `user_invocable`, `body`.
  Commands with `user-invocable: false` are skipped.
- Renderers, one per host, pure functions `(Workflow) -> str`:
  `render_vscode`, `render_codex`, `render_gemini`, `render_opencode`,
  `render_claude` (claude = passthrough of the canonical file). Every
  rendered file carries an ownership marker:
  - markdown: `<!-- generated by fettle workflows install -->` (after frontmatter)
  - TOML: `# generated by fettle workflows install`
- `install(agents, scope, repo_root, dry_run) -> list[Step]` (reuses
  `init_cmd.Step`). Write rules:
  - target missing → write, `created`
  - target exists with marker → overwrite only if content differs
    (`created`/`ok`)
  - target exists without marker → `action` (user-owned; never clobber) —
    same merge discipline as `init_codex`/`init_gemini`.
  - host not detected → `skipped` (detection mirrors init: `~/.codex`,
    `~/.gemini`, `~/.config/opencode`, `~/.claude` dirs; VS Code = repo
    `.vscode/` or `.github/` or `code` on PATH).

### Scopes and targets

| agent | `--project` (default) | `--user` |
|---|---|---|
| claude | `.claude/commands/fettle/<name>.md` — only when the plugin symlink is absent (plugin already provides `/fettle:*`); else `ok` | `~/.claude/commands/fettle/<name>.md` |
| vscode | `.github/prompts/fettle-<name>.prompt.md` | `action` — no stable user path; VS Code manages profile storage |
| codex | `action` — Codex has no project prompts; use `--user` | `~/.codex/prompts/fettle-<name>.md` |
| gemini | `.gemini/commands/fettle/<name>.toml` | `~/.gemini/commands/fettle/<name>.toml` |
| opencode | `.opencode/commands/fettle-<name>.md` | `~/.config/opencode/commands/fettle-<name>.md` |

### CLI

`fettle workflows install [--agent all|claude|vscode|codex|gemini|opencode]
[--project|--user] [--dry-run] [--json]` and `fettle workflows list`
(canonical names + per-host invocations). Exit 0 unless a write fails
(`error`); `action`/`skipped` are informational, matching `fettle init`.

### Wiring

- `fettle init` appends `workflows.install(detected_agents, scope="project"
  … codex→user)` steps — auto-parity on setup, honoring `--dry-run`.
- `doctor` probe `workflows`: for each detected host, expected files present
  and marker-owned → ok; missing/stale → warn with
  `fix: fettle workflows install`. Warn-only (missing workflows don't gate).
- README + docs/README: reworded — Fettle **workflows**, one table with
  per-host invocation syntax; drop "Claude Code plugin only" labels.

### Tests (~25)

Golden renders per host for one representative command (quality); TOML
escaping (quotes, backslashes, `"""` in body); `$ARGUMENTS`→`{{args}}`;
frontmatter parser (quoted values, missing keys, `user-invocable: false`
skip); marker idempotency (rerun→`ok`, edit-with-marker→overwrite,
strip-marker→`action`); scope matrix incl. codex `--project`→action, vscode
`--user`→action; `commands_dir()` resolution (env/clone/wheel via tmp dirs);
CLI exit codes + `--json`; init wiring; doctor probe; anti-drift — every
`commands/*.md` renders without error in all five renderers.

## Rejected alternatives

- **Symlinks instead of rendering** — Gemini needs TOML, VS Code needs
  `.prompt.md` extension + different frontmatter; symlinks can't bridge
  formats, and wheels can't ship symlink targets users own.
- **PyYAML frontmatter parsing** — would reintroduce the WP-11 problem
  (runtime dep or crash on bare installs). Frontmatter here is 5 flat string
  keys; a 20-line parser is safer than a dependency.
- **Codex skills instead of prompts** — skills are the anointed replacement
  but have a different contract (implicit invocation, SKILL.md bundles);
  prompts still work and match the "explicit slash command" UX of the other
  four hosts. Revisit when Codex actually removes prompts.
